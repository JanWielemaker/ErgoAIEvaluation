# TPLP benchmarks: ErgoAI on XSB vs ergoAIp

The benchmark set in `tplp_benches/` (transitive closure and Petri-net
reachability, written for the TPLP paper) run on both systems with the
same driver, `scripts/ergoaip_perf.pl`.  2026-10-26.

## Setup

| | |
|---|---|
| Machine | AMD Ryzen AI Max+ 395, 32 threads, 112 GB, Fedora 44 |
| XSB | xsb-code `ca3f56223` (2026-10-16), rebuilt 2026-10-26 |
| ErgoAI | ErgoEngine `e550962`, rebuilt against that XSB with `makeergo` |
| SWI-Prolog | 10.1.19, swipl-devel `f0aa4d6e6`, RelWithDebInfo |
| ergoAIp | ergoAIstudio2 branch `cache`, with this report's commit |

One program at a time, each in a fresh process, inside a systemd scope
capped at 90 GB; ergoAIp with a 60 GB table space and a 16 GB stack.

```
swipl scripts/ergoaip_perf.pl --engine=xsb --timeout=1800 --out=xsb.tsv tplp_benches/perf_suite.pl
swipl scripts/ergoaip_perf.pl --timeout=1800 --table-space=60g --out=swi.tsv tplp_benches/perf_suite.pl
python3 scripts/perf_report.py --compare xsb.tsv swi.tsv
```

`tplp_benches/perf_suite.pl` holds the 23 runs of the two
`bench_ergo.sh` scripts:

- **tc**: left-recursive transitive closure over a generated graph
  (`edge.pl`, a Prolog module called through `@\plg(edge)`), as a
  predicate and as a frame (`objid[reachable(L,F)->T]`), on a chain, a
  cycle and a chain with self loops, with 1M, 10M and 100M nodes.
- **elem_petri**: the states reachable in an elementary Petri net (a
  mutex unfolded N times, generated by the Prolog module `gen_elem.pl`),
  N from 100,000 to 2,000,000.  Generating the net is part of the goal;
  the time the benchmark reports is reachability only.

## Results

All 23 programs complete on both systems.  ergoAIp's solve time is
**2.2 times** XSB's (geometric mean; median 2.35, range 1.00-3.70).

| Family | ergoAIp / XSB | Peak memory at the largest size, XSB → ergoAIp |
|---|---|---|
| tc chain, cycle | 2.4-3.7, growing with size | 13.3 → 23.3 GB |
| tc self_loop | 1.9-2.3 | 13.2 → 23.3 GB |
| tc frame chain, frame cycle | 2.7-3.3 | 13.3 → 15.6 GB |
| tc frame self_loop | 1.7-2.1 | 13.3 → 15.6 GB |
| elem_petri | 1.00-1.05 | 12.3 → 24.3 GB |

- **Transitive closure** is where ergoAIp loses: 70-82 s against 20-37 s
  at 100M nodes.  The ratio grows from about 2.4 at 1M to 3.6 at 100M
  on the chain and the cycle, so the cost is per answer and grows with
  the table.  ergoAIp spends 17 inferences per answer on the plain
  predicate and 19 on the frame form.
- **Petri-net reachability** runs at the same speed on both: 178 s and
  182 s for the 2M net.  Both find the same number of states at every
  size (399,999 up to 7,999,999).
- **Memory**: ergoAIp needs 1.75 times XSB's peak on the HiLog
  predicates and about twice on elem_petri, but only 1.2 times on the
  frames.  The answer tries of a HiLog predicate are deeper (see the
  multiplicity tag in `ergoAIstudio2/CLAUDE.md`'s paper-bench notes).
- **Load** is negligible on both.  XSB's first load of a file includes
  about 0.4 s of compilation to `.xwam`; later loads take 0.04 s.
- The tc benchmarks print only their timing, so the *Same* column
  checks only that both ran the same instance; for elem_petri it
  compares the state counts.

*Solve* is the driver's measurement of the goal; *reported* is the
time the benchmark prints itself, which leaves out the generation of
the Petri net.

## What it took

These benchmarks are newer than the rest of the ergoAIp work and found
three bugs:

- `chain(…)@\plg(edge)` with no consult anywhere: XSB loads `edge.pl`
  from its library path, which includes the current directory, on the
  first call.  ergoAIp now does the same (`plg_module/1`).
- `elemNet.ergo` ends inside an unterminated `/*`.  ErgoAI's gpp, in
  its Flora mode, discards comments per file, so the comment ends with
  the included file; ergoAIp's gpp passed it on and it swallowed the
  rest of `bnergo.ergo`.
- `datum(elemNet,count(?Count),?Time)`: a `count/1` TERM whose argument
  is a variable was taken for the aggregate `count{…}`.

ErgoAI itself had to be rebuilt after XSB was: its first start
otherwise recompiles its C helpers, which fails with GCC 15 or later
(see "ErgoAI on XSB" in `tooling.md`).
